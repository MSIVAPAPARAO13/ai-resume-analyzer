# Testing Rules

1. **Pyramid Testing Strategy**:
   - **Unit Tests**: Test pure utility functions, Zod schemas, data transformers, and business logic using **Vitest**.
   - **Integration Tests**: Test Express API endpoints and database operations using **Supertest** and Vitest.
   - **End-to-End (E2E) Tests**: Test core user journeys using **Playwright**.
2. **Stable Locators in Playwright**:
   - Prefer user-visible roles (`getByRole`, `getByLabel`, `getByText`) or explicit test IDs (`getByTestId`).
   - Never use brittle CSS selectors, chained xpaths, or unstable autogenerated class names.
3. **Zero Arbitrary Timeouts**:
   - Never use hardcoded sleeps (e.g. `page.waitForTimeout(5000)`). Rely on auto-waiting assertions (`expect(locator).toBeVisible()`, web-first assertions).
4. **Isolated Test Environments**:
   - Ensure integration tests use ephemeral database states or transactions to prevent cross-test contamination.
5. **Phase Gate Enforcement**: All unit, integration, and E2E smoke tests must pass cleanly before advancing to any subsequent phase.
